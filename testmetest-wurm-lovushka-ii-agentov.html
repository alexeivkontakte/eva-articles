Червь testmetest: 42 реальных GitHub-репозитория минировали ловушками для Claude Code, Gemini и Cursor

29.10.2026 · по материалам первоисточника
JFrog Security Research обнаружила 42 «вооружённых» GitHub-репозитория, принадлежащих 11 законным владельцам: атакующие из npm-кампании testmetest заложили в нихисполнительные хуки, которые срабатывают, стоит открыть проект в ИИ-ассистенте или редакторе.

Ловушка срабатывает сама

Исследователи JFrog описали кампанию testmetest, выросшую из npm-червя семейства Shai-Hulud/Miasma. На этой неделе стало известно, что злоумышленники уже «заминировали» 42 реальных репозитория на GitHub у 11 уважаемых владельцев и организаций. В каждый внедрены конфигурации-хуки: `.claude/settings.json`, `.gemini/settings.json`, `.cursor/mcp.json`, правила Cursor и задания VS Code. Достаточно запустить Claude Code, Gemini или Cursor в таком проекте — или просто открыть его как рабочий пространственный каталог, — и скрытый файл `.github/init.js` выполнит полезную нагрузку.

Скрытый издатель и данные через цензор

По оценке JFrog, репозитории содержат полиморфные обёртки весом 12,9–13,7 МБ, которые декодируются в один и тот же CI-издатель: он ищет GitHub-токены и публикует отравленные версии npm-пакетов через GitHub Actions. Те же взятые аккаунты связаны с shellpanel-воркфлоу, атакующими internet-facing cPanel через критическую уязвимость CVE-2026-41940 (сквозная цепочка пока не доказана). Репозиторий атакующего работает и как активный шифрованный приёмник данных. Всего JFrog называет 15 npm-пакетов с хотя бы одной вредоносной версией. Ранний отчёт SafeDep от 22 октября не находил жертв — blobs просто были слишком велики, чтобы попасть в обычную поисковую выдачу GitHub.

Особенно коварный штрих

Червь устанавливает вайпер, который стирает домашний каталог, как только владелец отзовёт украденный GitHub-токен — классическая ловушка «не чини одним движением». Отдельная маскировка: скомпилированный native addon, не содержащий вредоносного кода и расшифровывающий `.napi_cache` только в рантайме.

Что делать разработчикам

JFrog рекомендует проверить репозитории на перечисленные хуки и файлы `.github/init.js`, ревизовать workflow и права публикации, отозвать потенциально утёкшие GitHub/npm-креды — но сначала снять вайпер (сверившись с индикаторами JFrog: службы `net-health-checker`, `pkg-runtime`, файлы в `/tmp/.svc` и `~/.local/share/runtimes/`), а заражённые системы пересобрать с нуля из доверенных источников.

Отдельного официального анонза GitHub или npm о компрометации платформы нет — речь о действиях злоумышленников, раскрытых приватными исследовательскими компаниями.
