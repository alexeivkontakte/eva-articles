Критическая дыра в Apache HTTP/2: одна функция отдавала удалённый запуск кода на серверах полугода

12.11.2026 · по материалам первоисточника
Apache закрыла критическую уязвимость CVE-2026-119618 в модуле mod_http2: ошибка синхронизации в функции assign_headers() позволяла удалённо выполнить код на веб-сервере. Патч вышел 11 ноября в версии 2.4.71, под ударом — все выпуски с 2.4.55 по 2.4.70, а это большинство работающих сегодня серверов Apache. Любопытная деталь: находку независимо друг от друга ИИ-сканер Anthropic и исследователи Google Cloud.

Что случилось

11 ноября Apache HTTP Server получил релиз 2.4.71 с критическим исправлением CVE-2026-119618. Уязвимость живёт в модуле mod_http2 — в функции assign_headers(), которая разбирает HTTP-заголовки. Проблема классическая для многопоточного кода: два потока обращались к общему ресурсу без правильной блокировки, портили кучу (heap corruption), а это при удачном стечении обстоятельств превращается в удалённое выполнение кода. Apache в собственной шкале рисков ставит «критический» уровень только туда, где удалённый атакующий реально может выполнить код на сервере — то есть потенциально червяком.

Кого это касается

Под ударом все версии Apache HTTP Server с 2.4.55 по 2.4.70 — это почти весь парк серверов, отдающих сегодня HTTP/2-трафик. Если mod_h2 ставился отдельно из GitHub, проверьте диапазон 2.0.8–2.0.42. CVE-запись пока в статусе reserved: публичного CVSS и подробного технического разбора нет, но администраторам совет простой — не ждать деталей, а обновляться до 2.4.71. Если обновиться прямо сейчас нельзя, временная мера — отключить HTTP/2 (модуль http2) до установки патча.

ИИ нашла, Google подтвердила

Любопытна хронология: 26 октября о находке в Apache сообщила команда Anthropic's OSS Scanner — автоматический сканер открытого кода на базе ИИ (внутренний идентификатор находки ANT-2026-MAPKT6MZ). Спустя неделю, 3 ноября, ту же ошибку независимо нашли люди — Энтони Уимс и Саймон Скэннелл из Google Cloud Vulnerability Research. Два обнаружения одной критической функции с разницей в неделю — хороший индикатор того, как ИИ-сканеры уже встроились в цепочку ответственного раскрытия: раньше «кто первый нашёл дыру» был чисто человеческим соревнованием.

Что делать клиентам и админам

Если ваш сайт, блог или сервис хостится на VPS с Apache — проверьте версию: `apachectl -v` (или `httpd -v`). Всё, что ниже 2.4.71 и выше 2.4.54, требует обновления в приоритетном порядке; на пакетных дистрибутивах патч придёт с обновлением дистрибутива чуть позже, на самописных сборках настраивать самому. Хостинг-провайдеру стоит проверить, не бегает ли где старая сборка, которую вы не пересобрали после 11 ноября.
