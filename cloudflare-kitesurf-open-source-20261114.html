Cloudflare открыла исходники Kitesurf: браузера, созданного для ИИ-агентов

14.11.2026 · по материалам первоисточника
Cloudflare выложила Kitesurf — свой браузерный движок для ИИ-агентов — в открытый доступ под лицензией Apache 2.0. Движок работает прямо в V8-изоляторах Cloudflare Workers без контейнеров браузера и потребляет заметно меньше ресурсов, чем Chromium, на типовых задачах агентов.

Браузер без браузера

12 ноября Cloudflare объявила, что Kitesurf — её движок для автоматизации веб-задач, изначально спроектированный под ИИ-агентов, — опубликован на GitHub под лицензией Apache 2.0. Теперь код можно изучить, запустить локально через Wrangler или развернуть собственный экземпляр на своём аккаунте Cloudflare. Движок парсит HTML, применяет CSS, исполняет JavaScript страниц и строит скриншоты — и всё это без запуска контейнера браузера, целиком поверх Workers. При этом сохранена совместимость с протоколом Chrome DevTools Protocol, так что к Kitesurf можно подключить привычные клиентские инструменты вроде Puppeteer.

Зачем агенту отдельный браузер

Kitesurf вышел в августе 2026 года как ответ на простую проблему: обычный Chromium, поднятый ради агента, жрёт память и CPU как полноценный пользовательский браузер, а агентов в облаке работают тысячи. Лёгкий движок в V8-изоляторах обходится заметно дешевле на массовых задачах — в Cloudflare продолжают публиковать прогресс по совместимости с веб-стандартами (Web Platform Tests) и бенчмаркам на сайте kitesurf.dev. Публичный playground позволяет попробовать движок ещё до развёртывания.

Осторожно:Experimental

Команда честно предупреждает: проект экспериментальный и активно разрабатывается, совместимость и точность рендеринга растут прямо сейчас. Важный момент для безопасности — у самостоятельного развёртывания Kitesurf нет встроенной аутентификации: свой экземпляр обязательно нужно закрывать Cloudflare Access или другим слоем авторизации, иначе агентовский браузер станет открытой дверью. Для контрибьюторов действует правило: сначала issue и одобрение мейнтейнера, потом pull request.

Почему это важно для агентских рантаймов

Браузер — самое опасное место, куда агент высовывает руки: там и промпт-инъекции со страниц, и чужие формы, и сессии. Собственный лёгкий движок с полным контролем исходников — это ещё и про безопасность: можно аудировать, что именно исполняется от имени агента, вместо того чтобы гонять в облаке чёрный ящик Chromium. Для открытой экосистемы агентских инструментов это серьёзный кирпичик: инфраструктура, на которой агенты «ходят в интернет», перестаёт быть проприетарной.
