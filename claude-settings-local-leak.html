ИИ-агент сам себя рассекретил: на GitHub нашли 1122 файла Claude Code с живыми паролями

08.11.2026 · по материалам первоисточника
Исследователи безопасности Apiiro обнаружили на GitHub 1122 публичные копии служебного файла Claude Code с реальными паролями, токенами и ключами — всего 1379 секретов. Команду «Да, и больше не спрашивай» агент запоминает дословно: вместе с паролем, набранным прямо в консоли.

Когда Claude Code в первый раз натыкается на опасную shell-команду, он спрашивает разрешение. Если разработчик жмёт «Yes, and don't ask again», агент сохраняет команду слово в слово в проектном файле `.claude/settings.local.json`, чтобы в следующих сессиях не приставать с вопросами. Проблема в том, что вместе с текстом команды в файл попадают пароли и токены, которые человек набрал прямо в ней, — открытым текстом.

Команда Apiiro прошерстила публичный GitHub и нашла 104 185 копий этого файла в 103 617 репозиториях. В 1122 из них (около 1,1%) хранился хотя бы один настоящий секрет, а всего — 1379 разных секретов. Больше трети открывают доступ к базам данных напрямую: 379 паролей от БД, 43 логина по SSH на публичные серверы, 42 токена GitHub, GitLab и npm, 23 ключа AWS. Среди владельцев файлов — 63 организации, в основном софтверные компании разных размеров; самые показательные кейсы: админский облачный ключ самого вендора баз данных и пароль владельца базы медицинских карт.

Агент коммитит сам себя

Claude Code пытается спрятать файл от git — но добавляет его только в личные глобальные исключения пользователя на его компьютере, а не в `.gitignore` самого проекта. Защита никуда не уезжает вместе с репозиторием, и в 539 из 1105 отследженных репозиториев файл меняли коммиты, где Claude указан соавтором, — то есть агент коммитил его собственными руками. Из 16 кодовых агентов, чью документацию сравнили исследователи, Claude Code единственный по умолчанию сохраняет полный текст согласованной команды в проектном файле.

Удаление файла ситуацию не спасает: старые версии остаются в истории git и в форках (211 форков 74 репозиториев несут те же секреты). С учётом истории файлов, общих командных настроек и сохранённых логов переписки итоговая цифра — 2539 секретов в 1994 репозиториях. На момент публикации исследования половина скомпрометированных файлов лежала на главных ветках не менее 217 дней, а одна из уведомлённых компаний подтвердила, что её ключ был живым.

Что делать, если вы пользуетесь агентом

Исследователи рекомендуют порядок, который стоит запомнить всем пользователям кодовых агентов: сначала ротация — сменить все пароли и ключи, которые когда-либо оказывались в таких командах, и только потом уборка. Далее: найти `.claude/settings.local.json` и `.claude/settings.json` по всей организации, включая историю git; убрать файл из-под версионирования (`git rm --cached`) и добавить в `.gitignore` репозитория; секреты передавать через переменные секрет-менеджера вроде `$DB_URL`, чтобы в сохранённом правиле оставалось имя переменной, а не значение; и согласовывать целые шаблоны команд (Bash(npm run:*)), а не единичные строки с встроенным паролем.

Отдельного анонса Anthropic по поводу находки нет — сам механизм документирован в официальных справочных страницах Claude Code, а разбирательство опубликовала Apiiro. Но вывод здесь по сути старый, просто подан новым инструментом: согласовывая агенту «не спрашивать больше», разработчик доверяет ему не только команду, но и всё, что было написано рядом.
