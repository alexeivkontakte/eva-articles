Malware внутри официального ИИ-фреймворка Microsoft: два релиза agent-framework на PyPI крали ключи Azure и CI/CD

19.11.2026 · по материалам первоисточника
Злоумышленники подменили официальные версии 1.26.1 и 1.26.2 популярного Python-пакета Microsoft Agent Framework — того самого, на котором разработчики строят собственных ИИ-агентов. Вредонос выкачивал учётные данные Azure, GitHub, Docker и Hugging Face и молча отправлял их на чужой вебхук; пакет качают около 200 тысяч раз в месяц.

Как малварь попала в официальный пакет

Исследователи OX Security обнаружили, что на PyPI были опубликованы две заражённые версии официального пакета agent-framework — 1.26.1 и 1.26.2. Судя по всему, атакующие получили доступ к учётным записям, которым доверена публикация релизов Microsoft: после того как заражённую 1.26.1 сняли и откатили на чистую 1.26.0, преступники залили ещё одну версию — 1.26.2 — с другим механизмом активации, но тем же вредоносом. Сам пакет — основной инструмент Microsoft для создания ИИ-агентов на Python (есть также .NET- и Go-версии), его скачивают в среднем около 192,5 тысячи раз в месяц.

Кража без единого импорта

Самое коварное — способ запуска. В Python-сборку попадал файл `agent_framework_meta.pth` с одной строкой `import agent_framework_meta`: такие файлы Python автоматически выполняет при каждом своём запуске, даже если фреймворк не импортирует. То есть достаточно один раз установить пакет — и считалка работает во всех проектах на этом интерпретаторе. Она собирает секреты окружения, облачные и пакетные учётки, токены управляемых идентификаторов Azure, OIDC-токены CI-конвейеров Azure DevOps и GitHub Actions, ключи Docker и Hugging Face — и выгружает всё на подконтрольный атакующим webhook.site в виде сжатой zlib и закодированной в base64 форме. При этом в зависимостях оставалась настоящая agent-framework-core 1.26.0, поэтому фреймворк продолжал нормально работать и компрометацию было легко не заметить.

Реакция Microsoft и Detection

Официального поста в блоге Microsoft пока нет — компания лишь подтвердила The Register, что расследует атаку, и на время следования временно скрыла часть своих репозиториев на GitHub. Первой публично разобрала атаку OX Security (17 ноября), Elastic Security Labs заявляет, что поймала вредонос через шесть минут после публикации, а Aikido насчитала 33 минуты между двумя заражёнными релизами. Chainguard заблокировал пакеты в своих образах.

Что делать, если ставили

Рекомендации исследователей: остановите активные проекты, изолируйте возможные заражённые машины, замените все учётные данные и токены, которые использовались на этих системах (Azure, GitHub, Docker, Hugging Face, реестры пакетов), и проверьте активность в затронутых сервисах. Простой «пакет же официальный, скачан с PyPI» больше не работает даже с логотипом Microsoft на обложке: цепочка поставок ИИ-инструментов теперь такой же вектор атаки, как и сами модели.
