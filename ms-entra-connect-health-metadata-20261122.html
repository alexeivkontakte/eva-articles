Microsoft призналась: взломали её собственный сервис Entra Connect Health — добычей злоумышленников стала «метадата» клиентов

22.11.2026 · по материалам первоисточника
Microsoft подтвервила взлом своего облачного сервиса мониторинга Entra Connect Health: с 23 июля по 19 ноября API отдавал посторонним метадату арендаторов и адреса почты админов. Исправление — серверное, но главным «вредоносным приложением» стал сам вендор.

Microsoft разослала администраторам уведомление о взломе собственного облачного сервиса Entra Connect Health — облачной службе мониторинга локальной инфраструктуры идентификации. Уязвимость в API появилась 23 июля 2026 года, компания обнаружила её 9 ноября, а 19 ноября развернула серверное исправление, не требуя от клиентов никаких обновлений. Расследование завершилось 20 ноября: подтверждён несанкционированный доступ только для чтения к метадате уровня арендатора, изменений в конфигурации не нашли.

Что именно утекло: адреса электронной почты технических контактов и администраторов, ID и названия арендаторов, исходные доменные имена, country-код и регион, тарифы лицензий Entra, статус синхронизации каталога (включая время последней синхронизации), статус подключения Connect Health, а также просроченный сертификат агентов, который API продолжал отдавать из хранилища. Пользовательские пароли, хэши, токены авторизации, действующие криптоключи, топология локального Active Directory и данные подписок Azure, по заявлению Microsoft, не пострадали.

Сколько организаций затронуто — не раскрывается; на на 21 ноября более десятка администраторов подтвердили получение уведомлений в профильных сообществах, а Managed-Service-провайдеры получили письма сразу за несколько клиентских арендаторов. Кода нет (CVE не присвоен), отдельного публичного анонса на блоге Microsoft нет — официальным источником служит именно уведомление внутри арендатора.

Показательная деталь для всей индустрии: уязвимость четыре месяца жила в API вендора, чья прямая обязанность — мониторить здоровье чужих систем идентификации, и клиенты узнали о ней только постфактум, через 10 дней после закрытия. «Доверяй, но проверяй» теперь применимо и к самим облачным «мониторам».

Что делать клиентам. Официальных действий по установке патча не требуется, но Microsoft рекомендует: предупредить службы безопасности о риске целевого фишинга и социнженерии на утёкшие адреса админов и данные арендатора; убедится, что привилегированные учётные записи используют MFA, устойчивый к фишингу; просмотреть конфигурацию Connect Health и журналы аудита/входов Entra на подозрительную активность. Проверить, какие поля метадаты относятся к вашему арендатору, можно официальным PowerShell-скриптом Microsoft (aka.ms/ConnectHealth/scripts). Российским организациям, сидящим на Entra ID через зарубежные тенанты, стоит как минимум обновить правила antifishing для адресов техконтактов.
