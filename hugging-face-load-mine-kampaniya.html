Вторая волна malware на Hugging Face: поддельные модели Qwen2 скачали 28 тысяч раз, а ловят они и ИИ-агентов

30.10.2026 · по материалам первоисточника
Исследователи Pluto Security описали кампанию Load/Mine: 31 вредоносный репозиторий на Hugging Face маскируется под крошечные тестовые чекпойнты Qwen2, устанавливает майнер и бэкдор на GPU-серверы — и возвращается через считаные дни после блокировок. Флагманскую модель скачали более 28 тысяч раз.

Модель без модели

Аналитики Pluto Security нашли 31 вредоносный репозиторий на семи аккаунтах Hugging Face, появлявшихся двумя волнами с сентября. Все они притворяются маленькими тестовыми чекпойнтами Qwen2 и нацелены на GPU-хосты с самостоятельными инференс-серверами — Xinference, GPUStack и аналогами. Связанные репозитории набрали более 32 тысяч загрузок (Pluto подчёркивает: это загрузки, а не подтверждённые заражения). Самая популярная модель MENXIANGYU/qwen2-tiny не содержала модели вообще — только код.

Как это работает

Кампания эксплуаттирует не «отравленные веса» и не pickle-уязвимости, а легальную опцию trust_remote_code: модель может поставлять собственный Python-код, который выполняется на машине пользователя в момент загрузки. Этот код ставит криптовалютный майнер, маскируясь под системный процесс Linux, перезапускает себя при убийстве и вычищает конкурентов-майнеров, а отдельные версии открывают reverse shell — прямой доступ атакующего к серверу. Пока исследователи наблюдали, девять машин исследовательского GPU-кластера одновременно начали майнить на оператора кампании; админ заметил это примерно через шесть минут.

Возврат после сноса

Первую волну удалили после обращения Pluto в Hugging Face и китайский ModelScope — но через несколько дней под новыми аккаунтами появилась вторая волна из 19 репозиториев, а через несколько часов после репорта оператор выложил модель со скриптом побега из контейнера. Восьмого дня после обращения вторая волна всё ещё была жива: счётчик флагманской модели вырос с 7354 загрузок до 28412, причём антивирусные сканеры площадки (в том числе от Protect AI и JFrog) выдавали «чисто» — они ищут известные сигнатуры, а не анализируют, что код модели делает по факту. Доход оператора — около 5000 долларов в криптовалюте Pearl (PRL); Pluto приписывает кампанию мотивированному деньгами китайскоязычному атакующему по комментариям в коде и C2-серверам на Alibaba Cloud.

Ловушка и для ИИ-агентов

В отдельном отчёте Air Security описывает фейковый Solana starter kit на GitHub (репозиторий живёт с ноября 2025-го, 286 звёзд): по сути это одно README без кода, которое ИИ-агенты-кодогенераторы находят первым по запросу и послушно выполняют — единственная «инструкция установки» собирает по частям URL и запускает в памяти PowerShell-загрузчик RAT. То есть жертвой ловушки может стать не только человек, скопировавший команду, но и агент, который прочитал README вместо разработчика.

Что делать, если вы загружали такие модели

Если вы поднимали подозрительные чекпойнты с trust_remote_code=True, считайте машину скомпрометированной: сверьте её с индикаторами компрометации из отчёта Pluto, ротируйте все доступные с неё учётные данные и ключи. Простая остановка майнера не спасает — вместе с ним ставились бэкдоры и reverse shell. Практика для всех, кто разворачивает открытые веса: не включать trust_remote_code для моделей из непроверенных аккаунтов, а агентам-кодогенераторам запрещать исполнение команд из README без человеческой проверки.
